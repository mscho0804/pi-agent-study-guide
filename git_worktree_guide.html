Git Worktree: 내 컴퓨터에 'AI 개발자 전용 작업실' 여러 개 만들기

이름은 거창해 보이지만 원리는 허무할 정도로 간단합니다. 한 번 이해하고 나면 왜 AI 에이전트 시대에 git stash 대신 무조건 git worktree를 쓰는지 바로 무릎을 탁 치게 됩니다!

기존 방식 (폴더 1개 = 브랜치 1개) 병목 발생

git checkout & git stash의 고통

  • • 상황: 내 폴더(my-app/)에서 Pi에게 "결제 리팩터링해 줘"라고 시켜서 파일 15개를 한창 고치는 중입니다.
  • • 돌발 상황: 갑자기 팀장님이 "로그인 버튼 안 눌리는 핫픽스 지금 당장 올려주세요!" 또는 "방금 올린 PR 코드리뷰 좀 해주세요"라고 합니다.
  • • 참사: Pi를 강제 종료하고 → 고치던 코드를 git stash로 숨기고 → 브랜치를 바꿨다가 돌아오면 작업 흐름과 컨텍스트가 완전히 박살 납니다.
Worktree 방식 (저장소 1개 = 폴더 N개) 멀티태스킹 치트키

git worktree: 공식 다중 분신술

  • • 핵심 원리: 무거운 .git 금고(커밋 역사, 브랜치 DB)는 원래 폴더에 딱 1개만 두고, 옆에 다른 브랜치가 열려 있는 새 작업 폴더만 1초 만에 뚝딱 연결해 줍니다.
  • • Pi와의 시너지: 1번 폴더에선 Pi 1호기가 결제 리팩터링을 계속 돌리게 놔두고, 나는 옆에 2번 폴더(Worktree)를 파서 Pi 2호기에게 핫픽스를 시키면 파일 충돌이 0%입니다!
  • • 왜 clone을 또 안 하고?: git clone을 여러 번 하면 용량도 배로 들고 서로 커밋이 공유되지 않지만, Worktree는 한 몸이라 어디서 커밋하든 즉시 공유됩니다.

🎮 인터랙티브 시뮬레이터: Worktree로 Pi 3명 동시에 굴리기

아래 버튼을 순서대로 눌러서 내 디스크에 어떤 일이 벌어지는지 직접 확인해 보세요!

# 실행된 터미널 명령어
$ cd ~/workspace/my-app && git worktree list
📁 ~/workspace/ (내 작업 폴더 구조)

초보자는 딱 이 4줄만 알면 끝납니다

복잡한 옵션 외울 필요 없이, 실무에서는 아래 4가지 패턴만 99% 사용합니다.

1. 새 브랜치 따면서 옆 폴더로 방 파기 가장 많이 씀 
git worktree add ../my-app-fix -b fix/login-bug

현재 폴더 바깥(../my-app-fix)에 새 폴더를 만들고, 그 안에 fix/login-bug라는 새 브랜치를 생성해 체크아웃까지 한 방에 해줍니다.

2. 이미 있는 원격/로컬 브랜치로 방 파기 PR 리뷰용 
git worktree add ../my-app-review feat/payment

이미 존재하는 feat/payment 브랜치를 별도 폴더에 즉시 열어줍니다. 내 작업을 멈추지 않고 동료의 PR을 돌려서 테스트할 때 최고입니다.

3. 현재 열려 있는 Worktree 목록 확인 상태 조회 
git worktree list

지금 내 컴퓨터 어디에 어떤 브랜치 작업실들이 열려 있는지 경로와 커밋 해시를 한눈에 보여줍니다.

4. 작업 끝난 방 깔끔하게 철거하기 정리 
git worktree remove ../my-app-fix

PR을 올렸거나 머지가 끝나서 더 이상 필요 없는 Worktree 폴더를 삭제하고 Git의 연결 목록에서도 깔끔하게 지웁니다.

⚠️ 초보자가 무조건 한 번은 겪는 주의사항 2가지
1. "이미 체크아웃된 브랜치입니다" 에러 (`already checked out`)
Git은 꼬임을 방지하기 위해 똑같은 브랜치를 두 폴더에서 동시에 여는 것을 막습니다. main이 본진에 열려 있다면 Worktree에서는 항상 새 브랜치(-b)나 다른 브랜치를 열어야 합니다.
2. node_modules나 .env 파일은 공유되지 않습니다!
Git이 추적하지 않는 파일(.gitignore 대상)은 새 Worktree 폴더에 자동으로 복사되지 않습니다. 새 Worktree에 들어가면 pnpm i(또는 npm i)를 한 번 실행하거나 아래 자동화 스크립트로 연결해 주면 됩니다.
