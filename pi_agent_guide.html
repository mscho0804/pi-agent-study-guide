Pi Coding Agent: 입문에서 실전 개조까지

이미 Copilot Usage / Limit 익스텐션을 직접 만들어보셨다면 기본기는 끝났습니다! 이제 Pi가 내부적으로 어떻게 돌아가는지, 왜 고수들이 열광하는지 핵심 메커니즘을 파헤쳐 봅시다.

# Core Philosophy
System Prompt: < 1,000 tokens
Default Tools: read, write, edit, bash
Extensibility: 100% TypeScript + Skills

왜 Pi는 기능이 별로 없는 것처럼 보일까? (의도된 극단적 미니멀리즘)

다른 에이전트들은 수만 토큰짜리 거대한 시스템 프롬프트와 수십 개의 내장 툴, 강제 플랜 모드를 기본 탑재합니다. 하지만 시스템 프롬프트와 툴 정의가 길어질수록 LLM의 추론 집중력(Instruction Following)은 급격히 떨어지고 컨텍스트 비용만 증가합니다. Pi는 이를 정면 돌파하기 위해 1,000 토큰 미만의 초경량 시스템 프롬프트와 단 4개의 원시 도구만 남겼습니다.

1. read
파일 내용이나 이미지를 읽어 컨텍스트에 적재합니다.
2. write
새 파일을 생성하거나 전체 내용을 덮어씁니다.
3. edit
기존 파일의 특정 코드 블록만 정밀하게 치환합니다.
4. bash
검색(rg, fd), 테스트, git, 빌드 등 모든 명령을 실행합니다.

인터랙티브 시뮬레이터: Pi의 1턴(Turn)이 도는 과정

아래 단계를 클릭해서 사용자 입력부터 익스텐션 훅, 툴 호출까지 어떻게 흐르는지 확인해 보세요.

Pi를 구성하는 4개의 내부 레이어

1. pi-ai 모델 추상화 계층

Anthropic, OpenAI, Google Gemini, GitHub Copilot, OpenRouter 등 15개 이상의 프로바이더 API와 구독(OAuth) 세션을 단일 스트리밍 인터페이스로 통합합니다. 만드신 Copilot Usage 익스텐션도 이 계층의 메타데이터와 맞닿아 있습니다.

2. pi-agent-core 상태 & 루프 엔진

대화 턴(Turn)의 생명주기, 메시지 큐, 툴 스케줄링과 실행 결과를 관리하는 심장부입니다.

3. pi-tui 터미널 렌더링 엔진

화면 깜빡임 없이 변경된 부분만 다시 그리는(Differential Rendering) 자체 제작 TUI 프레임워크입니다. 익스텐션으로 상태 표시줄(Status bar)이나 커스텀 오버레이 창을 띄울 수 있게 해줍니다.

4. pi-coding-agent CLI 하네스

우리가 터미널에 pi라고 쳤을 때 실행되는 패키지입니다. JSONL 트리 세션 저장, 컴팩션, 익스텐션/스킬 로더가 여기에 들어 있습니다.

Killer Feature #1

선형 채팅이 아닌 '방향성 트리(Directed Tree)' 세션과 /tree

코딩하다가 에이전트가 잘못된 라이브러리나 엉뚱한 방향으로 5~6턴 동안 삽질했을 때, 일반 에이전트에서는 "아니 그거 말고 다른 방법으로 해봐"라고 말해도 이미 실패한 코드와 에러 로그가 컨텍스트에 남아 모델을 계속 헷갈리게 만듭니다.
Pi에서는 /tree를 쳐서 삽질하기 직전 노드로 시간 여행(Rewind)한 뒤 새로운 가지(Branch)를 뻗어 깨끗한 컨텍스트로 다시 시작할 수 있습니다!

Killer Feature #2

컨텍스트 폭발을 막는 스마트 컴팩션 (/compact)

대화가 길어져 모델의 컨텍스트 한계에 가까워지면(기본 여유 임계치 16,384 토큰 도달 시 자동 실행, 또는 /compact 수동 실행), Pi는 무식하게 옛날 대화를 잘라버리지 않고 과거 턴만 요약본으로 압축하고 최근 작업 내역은 원본 그대로 보존합니다.

세션 히스토리 구조 변화
Turn 1~5
초기 파일 탐색 & 로그 (35k tok)
Turn 6~10
1차 리팩터링 시행착오 (40k tok)
Turn 11~15
테스트 실패 출력문 (30k tok)
Turn 16~20 (최근 20,000 토큰 보존 구간)
현재 수정 중인 파일 diff와 방금 나눈 대화 (원본 100% 유지)
📦 CompactionEntry (약 2k tok)
Turn 1~15의 핵심 결정사항, 수정된 파일 목록, 아키텍처 맥락만 구조화 요약! (105k → 2k로 다이어트)
Turn 16~20 (최근 20,000 토큰 원본 그대로 유지)
방금 작업하던 코드 맥락은 하나도 잃지 않고 쾌적한 속도로 다음 턴 진행!
💡 꿀팁: /compact 인증 모듈 리팩터링 결정사항 위주로 요약해줘 처럼 뒤에 지시사항을 붙이면 내가 원하는 포인트 위주로 압축합니다.

이 3가지를 구분하면 Pi 활용도가 10배 올라갑니다

이미 상태 표시줄에 Copilot Usage를 띄우는 익스텐션을 만들어보셨으니, 이제 언제 Context를 쓰고, 언제 Skill을 쓰고, 언제 Extension으로 툴을 만들지 기준을 잡을 차례입니다.

1. Project Context
AGENTS.md / CLAUDE.md

• 로딩 시점: 세션 시작 시 항상 100% 로드

• 용도: 이 프로젝트의 빌드 명령어, 폴더 구조, 절대 어기면 안 되는 짧은 코딩 규칙

• 주의: 너무 길게 쓰면 매 턴마다 토큰을 갉아먹으므로 핵심만 짧게 유지!

2. Modular Skills
.pi/skills/*/SKILL.md

• 로딩 시점: 평소엔 이름/한줄설명만 알고 있다가, 필요할 때만 Lazy Load!

• 용도: PR 작성 양식, DB 마이그레이션 절차, 사내 디자인 시스템 가이드 등 길고 상세한 매뉴얼

• 장점: 50개를 넣어놔도 평소 컨텍스트 소모가 거의 0에 수렴합니다.

3. TypeScript Extensions
.pi/extensions/*.ts

• 로딩 시점: Pi 런타임에 직접 마운트 (/reload로 핫리로드)

• 용도: UI 상태바 커스텀, 슬래시 명령어(/cmd), LLM이 호출할 새 도구(Tool) 추가, 이벤트 가로채기(가드레일)

• 장점: Pi 자체에 없는 기능을 코드로 무한 확장!

⭐ 핵심 구분: Tool vs Skill vs Command

pi.registerTool vs SKILL.md vs pi.registerCommand 완벽 비교

"누가 실행하는가(주체)"와 "LLM Request JSON의 어디에 포함되는가(토큰 비용)"만 알면 언제 무엇을 만들지 1초 만에 결정할 수 있습니다.

1. Tool (pi.registerTool) ≈ MCP 도구
🔧 신입 사원에게 쥐여준 "전동 드릴 (함수)"

AI가 원래 못 하던 물리적 행동(사내 API 호출, 인메모리 처리 등)을 코드로 만들어 LLM이 스스로 판단해 호출하게 합니다.

⚠️ 매 턴 Request JSON의 "tools": [...]에 전체 스키마가 포함되어 기본 토큰을 소모합니다.
2. Skill (SKILL.md) ≈ Claude Skill
📘 책상에 놓아둔 "업무 매뉴얼 책자"

새로운 함수를 짜는 대신, "PR 올릴 땐 bash 툴로 이 스크립트를 돌려라"처럼 기존 도구를 쓰는 노하우를 마크다운 글로 가르쳐줍니다.

✅ 평소엔 "system"에 1줄 요약만 들어가고, 필요할 때만 read로 읽는 지연 로딩(Lazy Load)!
3. Command (registerCommand) 슬래시 단축키
⌨️ 내 키보드에 달린 "전용 단축키 (/명령어)"

사람(나)이 채팅창에 /limit, /tree처럼 직접 쳤을 때만 로컬에서 즉시 실행되는 함수입니다.

⚡ LLM Request JSON에 아예 안 들어가며, 단독 실행 시 토큰 비용 0원 & KV 캐시 유지!
비교 항목 pi.registerTool(...) SKILL.md (Skill) pi.registerCommand(...)
실행 주체 LLM (AI 모델)이 문맥 보고 자동 호출 LLM이 필요할 때 읽거나, 내가 /skill:이름 호출 사람(사용자)이 /명령어 직접 입력
Request JSON 위치 "tools": [...] 배열에 전체 스키마 상시 포함 "system"에 이름+1줄 설명만 포함 (본문은 필요시 로드) 포함 안 됨! (LLM은 존재조차 모름)
토큰 / 비용 소모 도구 개수만큼 매 턴 기본 입력 토큰 소모 평소엔 거의 0 토큰 (사용할 때만 소모) 0 토큰 (내부에서 새 메시지를 안 보낼 경우)
리턴값의 행방 ToolResult가 다시 LLM에게 전송됨 매뉴얼 텍스트가 대화 히스토리에 읽혀 들어감 로컬 TUI 화면 알림/상태 변경 후 즉시 종료
언제 쓰면 최고인가? TUI 연동, 보안 API 통신 등 코드 실행이 필수인 AI 도구 사내 CLI 사용법, PR/커밋 규칙 등 대부분의 업무 워크플로우 Copilot 쿼터 확인(/limit), 캐시 타이머 등 UI/매크로 제어

익스텐션 레벨업: UI 표시를 넘어 '에이전트 개조'하기

Copilot Usage 표시에 성공하셨다면, 다음 단계로 바로 써먹기 좋은 3가지 익스텐션 패턴입니다.

🔥 Pi 고수들의 비기: 메타프로그래밍 (Pi에게 Pi를 개조시키기)

직접 익스텐션 문법을 다 외울 필요가 없습니다! Pi 안에서 "내가 /pr-check라고 치면 현재 git diff를 읽어서 사내 컨벤션 체크하는 익스텐션을 .pi/extensions/에 만들어줘"라고 시킨 뒤, 완성되면 /reload만 치면 재시작 없이 그 자리에서 바로 새 기능이 작동합니다.

회사에서 바로 쓰는 Pi 필수 명령어 & 단축키

/tree

대화 히스토리 트리를 열고 원하는 과거 시점으로 분기

필수
/compact [지시어]

최근 맥락은 남기고 이전 대화만 요약해 컨텍스트 확보

필수
/reload

방금 수정한 익스텐션(.ts)이나 스킬(SKILL.md) 즉시 반영

개발용
/model

대화 도중 다른 모델(Copilot, Claude, Gemini 등)로 즉시 교체

🚀 입문자 다음 단계 추천 루트

  1. 회사 프로젝트 루트에 짧은 AGENTS.md(빌드/테스트 명령어 5줄 요약)를 만든다.
  2. 반복해서 시키는 작업(예: 코드 리뷰, PR 본문 작성, 커밋 메시지 생성)을 .pi/skills/ 아래에 마크다운으로 정리한다.
  3. Copilot Limit 익스텐션 옆에 구독한 Gemini API를 서브 분석기로 부르는 커스텀 툴 익스텐션을 하나 추가한다.
  4. 두 번째 가이드인 Git Worktree와 결합해 여러 개의 Pi를 동시에 굴린다!
